Locator strategies (first matching element)

- find_element_by_id(id): The first element with the matching id attribute will be returned.
- find_element_by_name(name): The first element with the matching name attribute will be returned.
- find_element_by_xpath(xpath): The first element matching the xpath expression will be returned.
- find_element_by_link_text(text): The first anchor element with the exact link text will be returned.
- find_element_by_partial_link_text(text): The first anchor element containing the given text will be returned.
- find_element_by_tag_name(tag): The first element with the given tag name will be returned.
- find_element_by_class_name(name): The first element with the matching class attribute will be returned.
- find_element_by_css_selector(selector): The first element matching the CSS selector will be returned.

XPath (what and when)

XPath is a query language for selecting nodes from an XML/HTML document. In Selenium you can use XPath when other locators (id, name, class, CSS) are missing or unreliable.

Simple XPath examples:

- //tag[@attribute='value']      (select elements by attribute)
- //tag[text()='Visible Text']   (select element by exact visible text)
- //div//a[contains(@href,'login')] (use functions like contains() to match partial values)

When to use XPath

- The element doesn't have a unique id or name.
- The element is deeply nested inside the DOM and you need to traverse parent/child relationships.
- Other locators (CSS selector, id, class) fail to locate the element reliably.
- You need advanced selection (text matching, index-based selection, traversal).

Tips

- Prefer id/name/css selectors when possible (simpler and faster).
- Use XPath when you need DOM traversal or text-based matching.
- Keep XPath expressions as short and specific as possible to avoid brittle tests.
